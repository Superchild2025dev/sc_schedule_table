# 시간표 데이터 구조 V2

## 목표

현재 종류별 대형 JSON 문서를 원생, 수강, 자리, 상태, 기록 단위의 작은 문서로 분리한다.
화면 기능은 유지하되 한 자리 수정이 전체 원생 JSON을 다시 저장하지 않도록 한다.

## ID 규칙

- `personId`: 실제 원생 한 명의 영구 ID다. 이름, 전화번호, 반, 자리가 바뀌어도 유지한다.
- `enrollmentId`: 원생이 특정 시간표를 수강하는 관계의 ID다. 정규반과 방특반은 각각 별도 수강이다.
- `placementId`: 한 수강이 점유하는 요일, 시간, 레인, 순번의 ID다.
- `reservationId`: 등록, 제외, 퇴원, 이동 예약 한 건의 ID다.
- `requestId`: 학부모 요청 한 건의 ID다.
- `eventId`: 수정 기록 한 건의 ID다.

전화번호는 원생을 검색하고 병합 후보를 찾는 정보일 뿐 ID가 아니다. 형제가 같은 전화번호를 사용해도 이름과 원생 ID가 다르면 별개의 원생이다.

## Firestore 경로

```text
scheduleBranches/{branchId}
  people/{personId}
  tabs/{tabId}
  enrollments/{enrollmentId}
  placements/{placementId}
  teacherAssignments/{assignmentId}
  reservations/{reservationId}
  requests/{requestId}
  attendanceDays/{date}/slots/{slotId}
  auditEvents/{eventId}
  snapshots/{snapshotId}
```

## 문서 책임

### people

이름, 전화번호, 나이, 성별처럼 요일이나 수업이 바뀌어도 유지되는 정보만 보관한다.

### enrollments

정규, 방특 구분과 결제, 신규, 재등록처럼 한 수강에 속하는 정보를 보관한다.
같은 원생이 정규반과 방특반을 동시에 수강하면 두 개의 수강 문서가 생긴다.

### placements

요일, 시간, 레인, 순번과 승하차 위치, 해당 요일 메모를 보관한다.
승하차 정보는 원생 프로필에 넣지 않는다.

### reservations

등록예정, 제외예정, 퇴원예정, 이동예약, 휴원 예약을 한 건씩 보관한다.
취소할 때 예약 문서만 변경하며 원생이나 다른 자리 문서를 삭제하지 않는다.

### attendanceDays

날짜와 수업 슬롯별로 출석을 보관한다. 한 선생님의 출석 수정이 다른 시간대 출석 문서와 충돌하지 않게 한다.

### auditEvents

수정 기록은 덮어쓰지 않는 개별 이벤트로 저장한다. 화면에서는 처리일, 적용일, 운영월로 조회한다.

## 변환 순서

1. 기존 데이터와 탭 목록을 읽고 V2 변환 결과를 메모리에서 만든다.
2. 원생 수, 자리 수, 선생님 배치 수와 충돌 목록을 출력한다.
3. 충돌이 없거나 승인된 항목만 V2 컬렉션에 기록한다.
4. V1과 V2를 다시 읽어 수, ID, 자리 좌표를 대조한다.
5. 대조가 통과한 지점만 V2 읽기를 켠다.
6. 전체 회귀 테스트 후 V2 쓰기를 켠다.
7. V1 데이터는 복구용으로 남기고 쓰기만 중단한다.

## 전환 차단 조건

- 원생 ID가 없는 항목이 존재함
- 같은 시간표의 같은 자리에 서로 다른 원생이 존재함
- 하나의 원생 ID에 서로 다른 이름 또는 전화번호가 연결됨
- V1과 V2의 자리 수가 다름
- 정규반과 방특반의 수강 구분이 사라짐

이 조건 중 하나라도 발생하면 자동 전환하지 않고 진단 결과를 먼저 수정한다.
