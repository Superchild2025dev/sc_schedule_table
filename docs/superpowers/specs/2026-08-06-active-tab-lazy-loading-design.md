# 활성 시간표 탭 선택 조회 설계

## 목적

메인 시간표가 처음 열릴 때 모든 시간표 탭의 원생·담임 데이터를 한꺼번에 받지 않는다. 탭 목록과 운영 공통 데이터, 메인 시간표 데이터만 준비하고 다른 정규·방특·과거 시간표 데이터는 사용자가 해당 탭을 눌렀을 때 최신값을 조회한다.

이번 단계는 메인 시간표와 메인 화면에 통합된 출석부만 대상으로 한다. V1 저장 키, 쓰기 게이트웨이, 변경 분류 규칙, 선생님·데스크·설정 페이지는 변경하지 않는다.

## 현재 문제

현재 실시간 리스너는 지연 문서를 제외한 V1 문서를 모두 구독한다. 큰 스냅샷은 이미 선택 조회하지만 다음 문서는 비활성 탭이어도 첫 접속에서 내려받는다.

- 정규 탭 원생: swim_students, swim_stu_{tabId}
- 정규 탭 담임: swim_inst, swim_inst_{tabId}
- 방특 원생: swim_bt_{tabId}_stu
- 방특 담임: swim_bt_{tabId}_inst
- 방특 출석: swim_bt_attendance_{tabId}
- 방특 출석 추가원생: swim_bt_att_guests_{tabId}

결석·등록·제외·휴원·이동처럼 여러 탭이 함께 사용하는 V1 공통 맵은 현재 한 문서에 섞여 있다. 이 문서들은 이번 단계에서 계속 초기 공통 데이터로 읽는다.

## 선택한 방식

Firestore 저장소에 선택 키 구독을 추가한다. 초기 구독은 두 단계로 준비한다.

1. 탭 목록, 메인 탭 지정, 운영 공통 키를 구독한다.
2. 서버에서 받은 탭 목록과 메인 탭 지정을 기준으로 실제 메인 탭의 원생·담임·탭 전용 출석 키를 계산해 추가 구독한다.

두 단계가 모두 끝나기 전에는 메인 시간표 로딩 완료로 표시하지 않는다. 기존 전체 컬렉션 리스너를 먼저 열었다가 값을 무시하는 방식은 사용하지 않는다. Firestore에서 대상 문서 자체를 선택해 구독해야 실제 문서 읽기와 다운로드가 줄어든다.

## 대안과 판단

### 1. 선택 키별 문서 구독 - 선택

공통 키와 현재 탭 키만 문서 단위로 구독한다. 탭을 바꾸면 이전 탭 전용 구독을 해제하고 새 탭 키를 구독한다. 이전 탭 캐시는 화면 전환 속도를 위해 메모리에 남기지만 다시 열 때 서버 첫 스냅샷을 받은 뒤 사용한다.

### 2. 전체 컬렉션 구독 후 비활성 값 무시

화면 코드는 단순하지만 Firestore 문서는 이미 읽힌 상태라 비용과 다운로드 절감 효과가 작다. 탭을 눌러야만 가져온다는 요구를 충족하지 않는다.

### 3. 모든 공통 맵을 탭별 문서로 재분리

장기적으로 가장 효율적이지만 결석·등록·퇴원·보강·복원 범위를 함께 마이그레이션해야 한다. 운영 회귀 위험이 커서 별도 V2 전환 작업으로 남긴다.

## 키 분류

### 초기 부트스트랩 키

- swim_tab_list
- swim_archived_tabs
- swim_tab_folders
- swim_main_tab
- swim_parent_tab

### 초기 공통 키

현재 표, 권한, 배지, 운영 기간을 구성하는 다음 공유 데이터만 명시적으로 구독한다.

- swim_retire, swim_enroll, swim_mark, swim_disabled
- swim_reserve, swim_hyuwon, swim_move, swim_requests
- swim_attendance, swim_att_guests
- swim_closed, swim_teachers, swim_periods
- swim_retire_history, swim_desk_notes
- swim_age_year, swim_student_id_version, swim_ver
- 위 초기 부트스트랩 키 5개

기록 본문·복원점·날짜 스냅샷은 기존 지연 조회를 유지한다. 설정 전용 swim_aligo_settings와 swim_parent_feedback도 메인 화면에서 구독하지 않는다. 새 키가 추가돼도 무조건 공통으로 분류하지 않고 명시적인 분류 함수와 테스트를 거친다.

### 탭 전용 키

- 모든 일반 탭: 해당 탭 stuKey, instKey
- 방특 탭: 해당 탭 stuKey, instKey, attendance, attGuests
- 스냅샷 탭: 기존 swim_snap_{tabId} 지연 조회 유지

정규 출석과 정규 추가원생은 모든 정규 월 탭이 공통으로 사용하는 swim_attendance, swim_att_guests이므로 초기 공통 키에 남긴다.

## 구성 요소

### js/firebase-store.js

키 목록을 대상으로 하는 subscribeSelectedBatches 구독 API를 제공한다.

- 같은 키는 한 개의 문서 리스너만 가진다.
- 공통 키 리스너는 페이지가 닫힐 때까지 유지한다.
- 활성 탭 키 리스너는 탭 전환 시 교체한다.
- 여러 문서의 첫 스냅샷은 모두 준비된 뒤 초기 배치 하나로 전달한다.
- 같은 Firestore 커밋으로 연속 도착한 변경은 한 이벤트 루프 동안 모아 배치 하나로 전달한다.
- 삭제된 문서는 removedKeys로 전달한다.
- 큰 청크 문서는 지정된 키일 때만 청크를 조립한다.

구독 컨트롤러는 setActiveKeys, waitForActive, stop, diagnostics 기능을 제공한다.

### js/schedule-read-coordinator.js

기존 배치 검증·원자 적용·팝업 보류 기능을 유지한다. 선택 구독이 활성 탭 준비 상태를 알려주면 조정자는 그 탭 데이터가 모두 캐시에 적용된 뒤에만 탭 렌더를 허용한다.

### js/core.js

- 탭 메타데이터로 원생·담임·출석 키를 계산하는 순수 분류 함수를 둔다.
- 첫 화면은 원격 탭 목록과 메인 탭 설정으로 실제 활성 키를 확정한다.
- ensureScheduleTabLoaded(tabId, options)를 제공한다.
- 탭 전환 중에는 저장을 차단하고 현재 정상 화면을 유지한다.
- 탭 로드 실패는 페이지 전체 캐시를 지우지 않고 기존 탭으로 복귀한다.

### js/tabs.js

일반·방특 탭 클릭은 먼저 ensureScheduleTabLoaded를 기다린다. 준비 중에는 표 영역에 탭 이름과 불러오는 중만 표시한다. 연속 클릭은 증가하는 전환 번호로 구분하고 늦게 도착한 이전 탭 결과를 렌더하지 않는다.

스냅샷 탭은 현재 loadDeferredJSON 경로를 그대로 사용한다.

## 출석부 안전 규칙

### 현재 날짜와 같은 운영월

출석부 진입 전 현재 탭의 원생·담임 데이터와 해당 출석·추가원생 키가 준비돼 있어야 한다. 준비되지 않은 상태에서는 출석 버튼과 일괄 선택을 활성화하지 않는다.

### 월 경계를 넘는 주

표시하는 주의 날짜마다 getAttendanceBasisTabForDate로 기준 탭을 계산한다. 현재 탭과 다른 기준 탭이 하나라도 있으면 해당 탭의 원생·담임 데이터를 추가로 선택 조회한 뒤 출석표를 그린다.

예를 들어 수요일까지 5월 운영일이고 목요일부터 6월 운영일이면 한 주 출석부를 열 때 5월과 6월 기준 탭을 모두 준비한다.

### 과거 출석부

zz_swim_day_snapshot__{scope}__{date}는 현재처럼 날짜를 열 때만 조회한다. 날짜 스냅샷이 있으면 그 원생·담임을 우선 사용한다. 스냅샷이 없거나 구형 데이터라면 해당 날짜의 기준 탭 원생·담임을 조회한 뒤 기존 보정 규칙을 사용한다.

### 방특 출석부

방특 탭을 열 때 방특 원생·담임과 함께 그 탭의 attendance, attGuests를 준비한다. 다른 방특 탭의 출석 데이터는 그 탭을 누르기 전까지 읽지 않는다. 날짜 스냅샷은 정규와 마찬가지로 날짜 단위 지연 조회를 유지한다.

### 출석 저장

출석 체크, 일괄 체크, 출석부 원생 추가·삭제는 다음 조건을 모두 만족할 때만 저장한다.

- 현재 탭 전환이 완료됨
- 선택 날짜 기준 탭이 모두 준비됨
- 해당 출석 키의 첫 서버 스냅샷을 받음
- Firebase 읽기 전용 fallback 상태가 아님

조건을 만족하지 않으면 저장하지 않고 출석부 데이터를 불러오는 중이라는 안내를 표시한다.

## 데이터 흐름

### 첫 접속

1. 공통·부트스트랩 키 리스너를 시작한다.
2. 원격 탭 목록과 메인 탭 지정을 적용한다.
3. 실제 메인 탭 키를 계산해 구독한다.
4. 공통 키와 메인 탭 키가 모두 준비되면 캐시에 한 배치로 적용한다.
5. 기존 전역 메모리 구성과 표 렌더를 한 번 실행한다.

### 일반 탭 전환

1. 탭 전환 번호를 증가시키고 로딩 표시를 시작한다.
2. 새 탭의 원생·담임·탭 전용 출석 키를 구독한다.
3. 첫 서버 값이 모두 준비되면 캐시에 원자 적용한다.
4. 가장 최근에 누른 탭과 번호가 일치할 때만 활성 탭과 표를 바꾼다.
5. 이전 탭 전용 리스너를 해제한다.

### 출석 날짜 전환

1. 표시할 주의 날짜와 기준 탭을 계산한다.
2. 필요한 기준 탭 데이터를 병렬로 준비한다.
3. 필요한 과거 날짜 스냅샷을 병렬로 준비한다.
4. 전환 번호가 최신일 때만 출석표를 그린다.

## 오류 처리

- 탭 문서 일부가 실패하면 해당 탭으로 전환하지 않고 이전 화면을 유지한다.
- 원생 문서가 배열이 아니면 이전 정상 캐시를 보존하고 그 탭은 읽기 전용 오류로 처리한다.
- 탭 문서가 서버에서 실제로 존재하지 않는 경우에만 빈 원생·담임으로 확정한다.
- 네트워크 재연결은 Firestore SDK에 맡기며 동일 키에 중복 리스너를 만들지 않는다.
- 탭을 닫거나 다른 탭으로 이동한 뒤 도착한 결과는 현재 화면을 다시 그리지 않는다.
- 출석 기준 데이터 로드 실패 시 출석 저장을 차단하고 일반 시간표 데이터는 유지한다.

- 첫 접속의 모든 비활성 정규·방특 담임 문서

- 사용자가 실제로 연 탭과 출석 날짜 스냅샷

## 테스트

### 저장소

- 대상 키만 문서 리스너가 만들어진다.
- 비활성 키는 읽거나 청크를 조립하지 않는다.
- 활성 키 교체 시 공통 리스너는 유지되고 이전 탭 리스너만 제거된다.
- 여러 활성 문서 첫 값은 초기 배치 하나로 전달된다.
- 연속 탭 변경에서 해제된 키의 늦은 값은 현재 활성 배치가 되지 않는다.
- 문서 삭제와 구독 오류가 기존 정상 캐시를 지우지 않는다.

### 메인 시간표

- 원격 메인 탭 데이터가 준비된 뒤 한 번만 첫 렌더한다.
- 비활성 탭은 클릭 전 로컬 캐시만으로 렌더하지 않는다.
- 탭 클릭 중 저장이 차단된다.
- 빠른 연속 클릭에서 마지막 탭만 표시된다.
- 실패한 탭 전환은 기존 표를 유지한다.

### 출석부

- 같은 주에 두 운영월이 섞이면 두 기준 탭을 모두 준비한다.
- 과거 날짜 스냅샷이 있으면 비활성 원생 문서를 불필요하게 사용하지 않는다.
- 과거 날짜 스냅샷이 없으면 기준 탭을 불러온 뒤 보정한다.
- 방특 탭을 열기 전 방특 출석 키를 읽지 않는다.
- 출석 데이터 준비 전 개별·일괄 출석 저장이 차단된다.
- 날짜를 빠르게 바꿔도 마지막 주만 렌더한다.
