# 시간표 원생 변경 규칙 중앙화 설계

## 목표

퇴원, 제외, 횟수 줄임, 이동, 반 변경, 시간 변경, 일정 변경의 판정 규칙을 한 모듈로 통일한다. 기존 V1 키와 JSON 값, 화면 배치, 저장 관문은 변경하지 않는다.

## 현재 문제

동일한 판정이 `js/data.js`, `js/table.js`, `js/popup-stu.js`에 각각 구현되어 있다.

- 퇴원 예약의 `retireType`, `excludeReason`, `moveType`, 퇴원 이력을 화면마다 다르게 해석할 수 있다.
- 같은 이동을 하단 기록에서는 시간 변경, 팝업에서는 이동으로 표시할 수 있다.
- 특정 작업이 학생 배열에서 원생을 제거하면 별도의 일반 삭제 기록이 다시 생길 수 있다.
- 중복을 막기 위한 사후 필터가 늘어나 규칙을 변경할 때 수정할 위치가 많다.

## 검토한 접근

### 접근 A: 순수 판정 모듈 추가

저장과 UI는 유지하고 변경 종류를 판단하는 순수 함수만 별도 모듈로 만든다. 기존 전역 함수는 호환 래퍼로 남긴다.

장점은 변경 범위가 작고 기존 데이터와 화면을 보존하면서 단위 테스트가 가능하다는 점이다. 이번 단계에서 사용한다.

### 접근 B: 모든 원생 작업을 명령 처리기로 교체

버튼, 데이터 수정, 기록 생성을 하나의 큰 서비스로 동시에 교체한다. 최종 형태는 단순해질 수 있지만 퇴원과 예약 이동 등 운영 규칙의 동시 변경 범위가 너무 커 이번 단계에서는 사용하지 않는다.

### 접근 C: 하단 기록 필터만 추가

현재처럼 잘못 생성된 기록을 화면에서 숨긴다. 당장 증상은 줄지만 원인이 남고 중복 규칙이 더 늘어나므로 사용하지 않는다.

## 선택한 설계

`js/schedule-change-policy.js`를 추가한다. 브라우저에서는 `window.SCScheduleChangePolicy`, 테스트에서는 CommonJS 모듈로 제공한다.

공통 모듈의 책임은 다음과 같다.

- 슬롯 두 개를 비교하여 `일정변경`, `시간변경`, `반변경`을 판정한다.
- 예약 데이터와 퇴원 이력을 바탕으로 `퇴원`, `횟수줄임`, `이동`, `제외`를 판정한다.
- 화면 상태 문구인 `퇴원예정`, `횟수줄임예정`, `이동예정`, `제외예정`을 반환한다.
- 이동·퇴원 같은 구체 작업에서 파생된 일반 `삭제` 기록을 숨길지 판정한다.
- 사용자가 직접 누른 삭제는 절대 숨기지 않는다.

## 데이터 흐름

1. 기존 팝업이나 이동 함수가 현재와 동일한 V1 데이터를 저장한다.
2. 화면과 하단 기록이 예약 또는 이동 종류를 표시해야 할 때 공통 규칙을 호출한다.
3. 공통 규칙은 입력값을 변경하지 않고 표준 종류와 표시 문구만 반환한다.
4. 기존 화면 함수는 반환값을 그대로 사용한다.

## 호환 규칙

- `retireType: "retire"`는 항상 퇴원이다.
- `retireType: "exclude"`는 퇴원이 아니다.
- `excludeReason: "reduce"`는 횟수 줄임이다.
- `excludeReason: "move"`, `moveType`, 연결된 이동 예약은 이동이다.
- 명시 값이 없는 과거 데이터만 동일 원생·동일 슬롯·동일 날짜의 퇴원 이력으로 보완한다.
- 요일이 달라지면 일정 변경, 같은 요일에서 시간이 달라지면 시간 변경, 같은 요일·시간에서 레인 또는 번호가 달라지면 반 변경이다.
- 방학특강 기록을 정규 하단 기록에서 제외하는 기존 규칙은 유지한다.
- 수동 기록과 사용자가 직접 수행한 삭제는 유지한다.

## 오류 처리

판정 모듈은 Firebase를 호출하지 않고 예외 대신 보수적인 기본값을 반환한다. 불완전한 예약은 퇴원으로 추정하지 않고 `제외` 또는 `횟수줄임`으로 처리한다. 입력 객체는 수정하지 않는다.

## 테스트

- 명시적 퇴원과 퇴원 이력 보완 판정
- 이동, 횟수 줄임, 일반 제외 판정
- 일정·시간·반 변경 우선순위
- 구체 작업에서 파생된 일반 삭제 억제
- 수동 삭제 보존
- `data.js`, `table.js`, `popup-stu.js`가 공통 모듈을 사용하도록 하는 정적 검사
- 기존 퇴원·이동·하단 기록 회귀 테스트 전체 실행

## 완료 조건

1. 변경 종류 판정의 기준 구현이 `js/schedule-change-policy.js` 한 곳에 있다.
2. 기존 전역 함수 이름과 V1 데이터 형식은 유지된다.
3. 이동·퇴원·횟수 줄임에서 일반 삭제 기록이 추가로 표시되지 않는다.
4. 직접 삭제 기록은 유지된다.
5. 전체 자동 테스트가 통과한다.
