# 메인 시간표 조회·실시간 동기화 중앙화 설계

## 목적

메인 시간표의 초기 Firebase 조회, 메모리·로컬 캐시 반영, 실시간 변경 처리, 화면 갱신을 하나의 조정 계층으로 통일한다. 원생·담임·등록·제외처럼 한 작업에서 함께 바뀐 값이 서로 다른 시점의 화면으로 섞이거나, 늦게 끝난 이전 조회가 최신 데이터를 덮어쓰는 일을 막는다.

이번 단계는 메인 시간표만 대상으로 한다. 선생님 페이지, 데스크 페이지, 설정 페이지의 조회 구조는 변경하지 않는다.

## 현재 문제

현재 메인 화면은 다음 경로가 나뉘어 있다.

1. `loadFromFirebase()`가 루트 데이터를 한 번 조회해 `_dbCache`에 저장한다.
2. 초기 콜백이 `reloadBadgeMaps()`, `reloadGlobalData()`, `loadTabData()`를 순서대로 호출한다.
3. 별도로 `child_changed`, `child_removed` 리스너를 붙인다.
4. 변경 이벤트마다 캐시를 직접 수정하고 60ms 타이머로 화면 갱신을 예약한다.
5. 팝업이 열려 있으면 키 목록을 버리고 `_pendingSync` 플래그만 남긴 뒤, 팝업을 닫을 때 전체 메모리를 다시 구성한다.

Firestore에서는 초기 `get()` 뒤 실시간 리스너의 첫 스냅샷이 다시 도착한다. 저장소 계층이 같은 버전의 큰 값 재조립은 피하고 있지만, 초기 문서 조회와 메인 화면 반영 책임은 여전히 여러 파일에 분산되어 있다.

## 선택한 방식

기존 V1 데이터와 화면 함수는 유지하고, 그 앞에 `SCScheduleReadCoordinator`를 추가한다.

- Firebase 저장소는 초기 상태와 이후 변경을 **배치 단위**로 전달한다.
- 조회 조정자는 배치를 검증한 뒤 `_dbCache`와 localStorage에 한 번에 반영한다.
- 한 배치의 캐시 반영이 끝난 후 화면 갱신을 한 번만 요청한다.
- 초기 실시간 스냅샷을 초기 데이터로 사용하여 `전체 get + 리스너 초기 스냅샷`의 중복을 없앤다.
- Firestore가 아닌 RTDB fallback에서는 기존처럼 초기 `value` 조회 후 변경 이벤트를 사용한다.

## 대안과 판단

### 1. 얇은 조회 조정자 추가 - 선택

현재 전역 변수와 렌더러를 유지하면서 읽기 순서와 배치 반영만 통제한다. 수정 범위가 작고 되돌리기 쉽다.

### 2. 전역 상태 전체 재작성

`STUDENTS`, `RETIRE_MAP` 등을 새 상태 저장소로 바꾸면 장기적으로 깔끔하지만 모든 모달과 표 렌더러를 함께 수정해야 한다. 운영 회귀 위험이 너무 크다.

### 3. 활성 탭 문서만 선택 조회

첫 다운로드는 가장 많이 줄지만 탭 목록을 먼저 읽고 활성 탭의 학생·담임 키를 다시 계산해야 한다. 탭 전환 시 비동기 로딩 UX도 새로 필요하다. 이번 단계가 안정된 뒤 별도 작업으로 진행한다.

## 구성 요소

### `js/schedule-read-coordinator.js`

브라우저 전역 `window.SCScheduleReadCoordinator`와 CommonJS 테스트 export를 제공하는 순수 모듈이다.

책임:

- 초기 배치가 준비될 때까지 시작 완료를 보류한다.
- 배치마다 증가하는 세대 번호를 부여한다.
- 이미 더 최신 세대가 반영된 뒤 도착한 오래된 비동기 결과는 버린다.
- 여러 변경을 하나의 `{values, removedKeys, changedKeys, initial}` 배치로 정규화한다.
- 원생 키 값이 배열 JSON인지 검증한다.
- 같은 키의 같은 값을 다시 받으면 화면 갱신 대상에서 제외한다.
- 시작, 적용, 무시, 오류 상태를 진단 기록으로 제공한다.

조회 조정자는 Firebase, DOM, 전역 시간표 변수에 직접 의존하지 않는다. 캐시 저장, 화면 반영, 오류 표시는 생성 시 전달받은 함수로 호출한다.

### `js/firebase-store.js`

`FirestoreKVRoot`에 배치 구독 API를 추가한다.

```js
root.subscribeBatches({
  next(batch),
  error(error),
})
```

배치 형식:

```js
{
  initial: true,
  values: {swim_students: "[...]", swim_inst: "{...}"},
  removedKeys: [],
  changedKeys: ["swim_students", "swim_inst"]
}
```

Firestore의 첫 `onSnapshot`은 모든 현재 키를 읽은 뒤 초기 배치 하나로 전달한다. 이후 스냅샷은 실제로 버전이 바뀐 문서와 삭제된 문서만 묶어 전달한다. 큰 지연 키는 현재 규칙대로 제외한다.

기존 `on('child_changed')`, `on('child_removed')`, `once('value')` API는 선생님·데스크·설정 페이지 호환을 위해 유지한다.

### `js/core.js`

메인 화면에서만 조회 조정자를 생성한다.

- `loadFromFirebase(callback)`는 조정자의 초기 배치 완료 Promise를 사용한다.
- `_dbCache`와 localStorage 수정은 조정자의 `applyBatch` 콜백 한곳에서만 수행한다.
- `_attachFirebaseDataListeners()`의 직접 이벤트 처리는 제거하고 조정자 구독으로 대체한다.
- 원생 데이터 검증 실패 시 해당 배치 전체를 버리지는 않는다. 잘못된 원생 키만 유지 중인 이전 값으로 보존하고 다른 정상 키는 적용한다.
- 배치 적용 후 현재 팝업이 열려 있으면 화면 갱신만 보류한다. 변경된 키 목록은 보존한다.
- 팝업을 닫으면 누적된 키를 기준으로 한 번만 갱신한다.

## 데이터 흐름

### 첫 접속

1. 로그인과 지점 선택이 끝난다.
2. 조회 조정자가 `subscribeBatches()`를 시작한다.
3. Firestore 첫 스냅샷의 모든 비지연 값을 읽는다.
4. 조정자가 원생 배열과 JSON 값을 검증한다.
5. 유효한 초기 배치를 `_dbCache`와 localStorage에 원자적으로 반영한다.
6. 기존 초기화 함수가 전역 메모리와 표를 한 번 구성한다.

초기 배치가 성공하기 전에는 `_firebaseLoaded`를 `true`로 만들지 않는다.

### 원격 변경

1. 한 Firestore 커밋에서 변경된 문서들을 모두 읽는다.
2. 저장소가 배치 하나를 조정자에게 전달한다.
3. 조정자가 같은 값과 오래된 세대를 제거한다.
4. 남은 키를 캐시에 모두 적용한다.
5. `reloadGlobalData()`, 필요 시 `loadTabData()`, `reloadBadgeMaps()`, `buildTable()`을 한 번씩 호출한다.

### 팝업 편집 중

1. 원격 배치는 즉시 캐시에 반영한다.
2. 변경 키는 누적하지만 표는 다시 그리지 않는다.
3. 팝업을 닫으면 누적 키를 한 배치로 처리한다.

## 오류 처리

- 원생 키가 배열이 아니거나 JSON 파싱에 실패하면 해당 키의 이전 정상값을 유지한다.
- 초기 배치에서 활성 원생 키가 유효하지 않으면 서버 로드 성공으로 표시하지 않고 읽기 전용 fallback으로 전환한다.
- Firestore 리스너 오류는 한 번만 보고하고 기존 캐시를 읽기 전용으로 유지한다.
- 리스너 재연결은 Firestore SDK에 맡기며 별도 중복 리스너를 만들지 않는다.
- RTDB fallback은 기존 동작을 유지한다.

## 조회량 변화

이번 단계에서 해결되는 부분:

- Firestore 초기 `get()`과 실시간 리스너 첫 스냅샷의 중복 경로 제거
- 실시간 변경마다 동일 값을 다시 화면에 반영하는 작업 제거
- 여러 키 변경 시 렌더링과 메모리 재구성 횟수 감소
- 지연 키가 초기 조회에 포함되지 않는 현재 정책 유지

이번 단계에 남는 부분:

- 첫 접속에서는 현재 운영에 필요한 모든 비지연 V1 키를 한 번 읽는다.
- 비활성 시간표의 학생·담임 문서까지 선택적으로 제외하는 작업은 후속 단계다.

## 테스트

### 순수 조정자 테스트

- 초기 배치는 한 번만 준비 완료를 알린다.
- 한 배치의 여러 키를 한 번에 적용한다.
- 같은 값은 재렌더링하지 않는다.
- 늦게 완료된 오래된 세대가 최신값을 덮어쓰지 않는다.
- 잘못된 원생 값은 이전 정상값을 보존한다.
- 팝업 중 변경 키를 잃지 않고 나중에 한 번 갱신한다.

### Firebase 저장소 테스트

- 첫 리스너 스냅샷이 초기 배치 하나로 전달된다.
- 첫 로드 뒤 동일 버전 문서는 다시 조립하지 않는다.
- 한 커밋의 여러 문서가 배치 하나로 전달된다.
- 삭제 문서가 `removedKeys`에 포함된다.
- 구독 해제 후 콜백이 호출되지 않는다.

### 회귀 테스트

- 기존 메인 시간표 전체 테스트
- 원생 자리 충돌 보호
- 쓰기 게이트웨이와 저장 권한 테스트
- 방특·출석·스냅샷 테스트
- 전체 `tests/*.test.js`

## 범위 밖

- V1 문서 구조 변경
- V2를 운영 원본으로 전환
- 선생님·데스크·설정 페이지 조회 리팩터링
- 활성 탭만 선택 조회
- 화면 디자인 변경
