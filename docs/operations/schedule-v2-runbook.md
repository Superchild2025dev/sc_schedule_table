# Schedule V2 운영 전환 및 복구 안내

이 문서는 정규반과 방학특강 시간표를 V1에서 V2로 안전하게 전환하고, 이상이 생기면 V1로 되돌리는 절차를 설명한다. 학부모 페이지는 별도 전환 대상으로 다룬다.

## 기본 원칙

- 전환 순서는 반드시 `v1 -> shadow -> verify -> v2-read -> v2`를 지킨다.
- 가경점과 용암점은 각각 확인하되, 한 지점의 이상을 다른 지점 정상으로 간주하지 않는다.
- `revision`만 증가한 것은 다른 기기의 정상 저장일 수 있다. 이 경우 화면 전체를 새로고침하거나 전환을 되돌리지 않는다.
- `mode`, `generationId`, `epoch`가 예상과 다르면 저장을 멈추고 권한 전환 상태부터 확인한다.
- 복구를 위해 V2 세대 문서를 삭제하지 않는다. 전환 모드만 V1로 되돌린다.

## 공통 통과 조건

각 단계로 넘어가기 전에 가경점과 용암점 모두 아래 조건을 만족해야 한다.

1. V1 미러 복구의 `pending`, `processing`, `error` 건수가 모두 0이다.
2. 학부모 요청 복구의 `pending`, `processing`, `error` 건수가 모두 0이다.
3. V1/V2 불일치 건수가 0이다.
4. 선택한 세대가 검증 완료 상태이며 현재 `generationId`와 일치한다.
5. 정규반과 방학특강의 원생 수, 자리, 선생님, 결석·보강, 출석부가 일치한다.
6. 서로 다른 원생을 동시에 수정한 테스트와 서로 다른 출석을 동시에 체크한 테스트가 통과한다.
7. 다른 기기의 revision 증가만으로 화면 새로고침 안내가 발생하지 않는다.
8. 진단 화면과 로그에 이름, 전화번호, 요청 본문이 노출되지 않는다.

한 항목이라도 실패하면 다음 단계로 넘어가지 않는다.

## 단계별 전환

### 1. V1

- 운영 데이터는 V1이 기준이다.
- V2 후보 세대를 새로 준비하고 전체 변환 검증을 실행한다.
- 기존 운영 시간표를 수정하거나 삭제하지 않는다.

### 2. Shadow

- 화면 읽기와 저장 기준은 계속 V1이다.
- V1 변경을 V2 후보에 복사하고 불일치 수만 관찰한다.
- 이 단계에서 불일치가 생기면 원인을 고친 뒤 새 후보 세대를 준비한다.

### 3. Verify

- V1 저장 후 V2 반영과 선택 영역 비교가 끝날 때까지 성공으로 표시하지 않는다.
- 가경점과 용암점에서 정규반 및 방학특강의 원생 이동, 선생님 변경, 결석·보강, 출석 체크를 각각 시험한다.
- 공통 통과 조건을 모두 만족한 상태로 충분히 관찰한 뒤 진행한다.

### 4. V2 Read

- 화면은 V2를 읽고 모든 저장은 인증된 Functions 경로로 처리한다.
- V1은 복구용 미러로 유지한다.
- 서로 다른 원생 또는 출석을 동시에 수정했을 때 둘 다 남는지 확인한다.
- 같은 원생 또는 같은 출석을 동시에 수정하면 한쪽만 저장되고 다른 쪽에는 다시 확인 안내가 나와야 한다.

### 5. V2

- V2를 운영 기준으로 확정한다.
- V1 미러 복구 대기 건수가 0인 상태를 계속 유지한다.
- 전환 직후에는 원생 이동, 퇴원 예약, 결석·보강, 출석부, 스냅샷을 집중 관찰한다.

## 즉시 중단 또는 되돌리기 조건

다음 중 하나라도 발생하면 신규 편집을 잠시 멈춘다.

- 예상하지 않은 `mode`, `generationId`, `epoch` 변경
- V1/V2 불일치 건수 1건 이상
- 복구 `error` 1건 이상 또는 `pending`/`processing`이 계속 증가
- 저장 성공 안내 후 원생, 출석, 결석·보강이 다른 기기에서 보이지 않음
- 같은 작업이 중복 적용되거나 다른 원생의 자리를 덮어씀
- 권한 오류가 여러 계정 또는 두 지점에서 반복됨
- 진단 로그에 이름, 전화번호 또는 요청 본문이 노출됨

## 되돌리기 절차

1. 데스크에 편집을 잠시 중단하도록 알린다.
2. 현재 mode, generationId, epoch, revision과 복구 건수를 기록한다.
3. 개발자 계정의 전환 화면에서 공식 rollback 동작을 실행한다.
4. 시간표와 출석부의 운영 포인터가 함께 V1로 바뀌고 epoch가 증가했는지 확인한다.
5. V1 화면에서 정규반과 방학특강의 원생, 결석·보강, 출석부를 확인한다.
6. 커밋된 V2 작업의 V1 복구 큐를 처리하고 `pending`, `processing`, `error`를 모두 0으로 만든다.
7. 마지막 검증 완료 세대와 현재 V1을 비교해 불일치 원인을 기록한다.

되돌리기 중 V2 문서나 세대를 삭제하지 않는다. 원인 분석과 재전환에 필요한 증거이기 때문이다.

## 배포 후 관찰

- 첫 30분: 5분 간격으로 두 지점의 불일치와 복구 건수를 확인한다.
- 첫 운영일: 원생 이동, 퇴원, 결석·보강, 출석 체크 후 다른 기기에서 결과를 확인한다.
- 다음 운영일: 전날 출석부와 스냅샷이 날짜 및 탭에 맞게 다시 열리는지 확인한다.
- 이상이 없더라도 승인 커밋 SHA와 마지막 검증 세대는 운영 기록에 남긴다.
